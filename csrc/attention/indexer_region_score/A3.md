# A3 BF16 IndexerRegionScore

The A3 implementation accepts native BF16 query and key tensors and
FP16, BF16 or FP32 head weights. It uses BF16 MMAD, an FP32 GM bridge,
and FP32 weighted reduction. The existing ACLNN interface supports full
scores and IDs-only execution. The Torch ids_out entry also accepts A3 BF16.

The causal visibility formula, paged cache addressing, ReLU-before-weighting,
four-head reduction grouping, tie-breaking by smaller logical ID, ascending
output IDs and minus-one padding follow the A5 implementation in PR #20946.
Only causally visible scores are defined.

## Workspace

Let C be the used Cube count and L the CANN library workspace prefix.
Full-score algorithm workspace is align32(L) + 131072*C bytes. Relative to
the same L, the extra reservation is 128 KiB per Cube plus 0–31 alignment
bytes, giving 3 MiB for 24 Cubes and 4 MiB for 32 Cubes. IDs-only charges
the bridge inside the existing 256 MiB algorithm budget and computes a
bounded token batch. A shape is rejected if one token cannot fit.
Input materialization and executor allocations add to GetWorkspaceSize.

## Initial bring-up validation (2026-11-16)

The reference is independent FP64 scoring over the actual BF16 input bits,
with scaled weights rounded to FP32. The diagnostic score criterion was
abs_error <= 1e-4 + 1e-5*abs(golden), together with exact mathematical TopK IDs.

- CANN 8.5.0 standalone A3 package compilation passed for all three weight types.
- Official Ascend910_9391 CA simulation passed 13 core cases, two additional
  G/H shapes and two R=16385 cases with K=511/512, in both output modes.
- Repeated defined scores and IDs, output guards and input immutability passed.
- IDs-only forced batching used 14+3 tokens with 254804992 bytes of complete
  executor workspace and exact expected IDs.
- 910B2C compatibility execution additionally passed 13 strided-view cases.
- Across 37050 defined scores, A3 simulation and 910B2C compatibility were
  bit-identical. Correctly rounded FP64 golden matched 24014/37050 scores
  bitwise, including 16385 zeros from the long tie case.
- Core maximum absolute error was 6.468480862e-6. Additional shape cases
  stayed below 3.392642210e-6, and long-sequence cases below 5.507196504e-7.

The installed SDK aliases the Ascend910_9391 simulator directory to
Ascend910B1. A3 hardware, A5/A3 bit equivalence, full repository build,
Torch integration tests and model-level precision still require validation.
A3 strided-view simulation stopped in the SDK AsStridedAiCore input
materialization because its A3 built-in binary configuration was missing.

## Numerical limits

Three of four numerical stress cases failed strict FP64 acceptance in both
simulation and compatibility hardware execution.

- Large signed head cancellation produced maximum absolute error
  0.4912499483 and maximum relative error 71.86%. IDs agreed in that case.
  The observed quartet arithmetic matched separately rounded FP32 multiply
  and add. The A5 instruction's actual rounding requires A5 execution.
- A near TopK boundary changed IDs through FP32 rounding, with maximum
  score error 5.960464478e-8.
- BF16 subnormal inputs produced zero scores and different mathematical
  TopK IDs, with maximum absolute score error 2.582873329e-40.

These failures remain unresolved. The standalone implementation has no
published A3 hardware performance result.

## Optimized kernel validation (2026-11-17)

The optimized kernel bundles four H=4 queries, coalesces adjacent key rows,
caches verified contiguous page prefixes per request, and uses a vector
threshold plus stable logical-ID compaction for up to 1024 visible regions.
Larger selections retain the bounded heap fallback. FP32 quartet arithmetic
and the workspace formula are unchanged.

On the specified BF16 workload, all 5,197,856 defined score words and all
TopK IDs match the previous A3 kernel bitwise. The independent FP64 score
criterion and exact mathematical IDs pass at all three KV lengths. Twenty-seven
ordinary/shape/boundary/view cases pass; four numerical stress cases retain
the previously documented limitations, with no new bit differences across
31 cases. Three focused CA simulation cases pass, including request page-base
changes, ties and partial masks. The optimized A3/compatibility objects match
bytewise.

These measurements are **910B2C compatibility results**, not A3 hardware
results. See [the performance report](A3_PERFORMANCE.md), its machine-readable
record, and the standalone reproduction harness in benchmarks/a3_bf16.

## Repository test entry

After building the A3 custom operators and extension, run from the repository root.

```bash
pytest -v tests/e2e/nightly/single_node/ops/singlecard_ops/test_indexer_region_score.py
```

The existing exact dyadic oracle tests now run BF16 cases on A3 and cover
non-aligned head counts and paged cache tails. The repository Torch integration tests
remain pending; their source has syntax validation in the development environment. Native ACLNN
validation above used the separately built standalone harness.
